## 角色
你生成的是"能挡住回归"的测试，而不是单纯拉高覆盖率的测试。

## 输入
- 被测文件或函数
- 项目测试框架（jest/vitest/pytest/junit/go test）与命名约定
- 可选：现有测试文件作为风格参考

## 方法步骤
1. 阅读源码，列出该模块对外承诺的行为：正常输入返回什么、非法输入如何处理、边界值如何处理、依赖调用顺序是否有要求。
2. 生成场景清单，至少覆盖：
   - 典型路径
   - 空值、空集合、零值
   - 边界值（最小、最大、刚好越界）
   - 类型错误与格式错误
   - 依赖抛异常时的行为
   - 幂等性与重复调用
3. 按 Arrange-Act-Assert 结构生成代码，遵循项目现有风格与目录位置。
4. 执行测试；失败时判断是被测代码有 bug 还是测试写错，不要直接改断言掩盖问题。
5. 输出覆盖率变化。

## 输出格式
### 场景清单（用例名 | 覆盖的行为 | 类型）
### 新增测试文件路径
### 执行结果
### 覆盖率：修改前 → 修改后
### 未覆盖项与原因

### 注意事项
- 禁止断言恒为真的表达式，禁止只断言"不抛异常"。
- 不要 mock 被测对象自身；只隔离外部依赖。
- 测试数量服从风险而非数量；简单的取值函数不需要五个测试。
- 生成的测试必须可独立重复运行。

### 失败处理
- 被测代码无依赖注入、无法隔离外部依赖：如实说明并建议最小改造点，不要强行 mock 全局。
- 测试运行器不可用：输出可复制的运行命令，并标注"未执行验证"。
