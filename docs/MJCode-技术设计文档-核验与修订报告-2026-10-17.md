## 0. 先说清楚：为什么"每次修完又冒一批"

前两轮都栽在同一处：**改的是错字，没改产生错字的机制**。本文档有四类"不会自愈"的缺陷生成器：

| # | 生成器 | 表现 | 为什么抽查抓不住 |
|---|---|---|---|
| G1 | **手写数字快照，无单一事实源** | 套件数曾同时存在 117/116/123/115/120 五个值；IPC 168/178；`main.js` 1490/1425 | 抽查只会碰到其中一个值，其余四个仍在文档别处存活 |
| G2 | **修复只改第 9 章 X 表，不回填章级 R** | X1/X3/X5/X11/X22 标了「✅ 已修」，但第 5/6/7 章对应的 R2/R3/R4/R6/R8 仍写"未修" | 抽查看 X 表会认为"都修了"，看章级 R 会认为"都没修"——两处都像真的 |
| G3 | **否定式断言（"全仓无 X""0 处""唯一"）没有复验** | 第 7 章 R6「全仓无 allowPrerelease」——实际存在 | 否定命题只要漏扫一次就永久错；而它读起来最"确定" |
| G4 | **章内编号跨章漂移** | 8 处「第 11 章 R1」——全文只有 10 章，指的是第 7 章 §11 | 单看一句话完全通顺，只有全文扫章号才暴露 |

**本轮止损做法**：不再抽查，改为对全文做**可复跑的穷举检查**（口径见 §2），并把"哪些查过、哪些没查"写进文档，让下一轮从没查过的地方开始。

## 5. 止损机制（已落地）

上表 4 个生成器，对应 4 条可落地的机器校验。建议做成 `desktop/scripts/doc-fact-check.mjs`，**不接入 `npm test`**（避免又造一个"红绿全凭运气"的门禁），由发版前或改文档后手动跑：

已落地为 **`desktop/scripts/doc-fact-check.mjs`**（零依赖、按需运行、**不接入 `npm test`**——避免再造一个"红绿全凭运气"的门禁）：

```bash
cd desktop
node scripts/doc-fact-check.mjs                 # 校验默认文档
node scripts/doc-fact-check.mjs --doc ../docs/x.md
node scripts/doc-fact-check.mjs --quiet         # 只输出问题（适合 CI 摘录）
```

它覆盖四类生成器中的三类，全部**从源码现算再与文档比对**，不与写死的常量比：

| 生成器 | 检查 | 现算口径 |
|---|---|---|
| G1 数字快照 | 套件 / IPC 通道 / preload 桥方法 / 主进程 JS 模块数 / `main.js` raw 行 | 扫 `test/*.test.*`、`ipcMain.handle\|on` + `WRITE_TOOLS` 展开 + `diff:comment`、`preload` 顶层键、`find`、`wc -l` |
| G2 状态回填 | X 标 `✅ 已修`，对应「第 N 章 R M」必须含 `✅`/`已修` | 按章区间定位 R 行，避免同名 R 串味 |
| G4 悬空引用 | 章号存在、`X/R/D/Q/J/A` 编号已定义、`文件:行` 可解析且不越界 | 多基址回退 + 行号范围 |
| 表格 | 每个表格块列数一致 | 按 `\|` 切分比对表头 |

**反向验证（这一步比脚本本身重要）**——故意制造 5 类变异，确认它真的会红：

| 变异 | 期望 | 实测 |
|---|---|---|
| `126 套件` → `117 套件` | 数字漂移 | ✅ `数字漂移：suites 文档写 117，源码现算 126` |
| `raw 1432` → `raw 9999` | 数字漂移 | ✅ 同上 |
| 插入「见第 12 章」 | 悬空章号 | ✅ `悬空章号：第 12 章（实有 1/2/…/10）` |
| 去掉第 7 章 R2 的 `✅`，保留 X1 的 `✅` | 状态不一致 | ✅ `状态不一致：X1 标注已修，但第 7 章 R2 仍写作未修` |
| 基线（未变异） | 绿 | ✅ 0 错 0 警 |

> 期间修掉一个**哑校验点**：初版把 `~~` 删除线也当作「已回填」标记，导致"只留删除线、漏掉 ✅"的 R 行判定为绿——反向验证第 4 条正是用来抓这个的。**没有反向用例的校验点等于没校验。**

G3（否定式断言）无法自动判真伪，脚本只做**清单提醒**（当前 92 条），要求人工各附一条可复跑命令。

**三条更省的纪律**（成本从低到高）：

1. **数字只写一次**：「关键数字速查」表是唯一出处，正文一律写「见速查表」，从结构上消灭 G1 的多值并存。
2. **修复必须双写**：改 X 表时，同一个提交里改对应章级 R（G2）；否则 X 表越全，章级 R 越假。
3. **否定式断言必须交命令与正样本**：写「全仓无 X」时，附可复跑命令 + 一处正样本证明检索有效（文档第 10 章 J1 已经吃过这个亏：`grep` 空输出被读成"零使用"）。
