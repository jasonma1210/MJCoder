# 对话流程审查：与主流 Agent 交互设计对照

| 项 | 值 |
|---|---|
| 触发 | 用户实测：任务没跑完就断开（日志显示 3 个 run 全被「渲染层信号」中止）+ 6 个技能全部拒绝注入 |
| 结论 | **不是架构问题，是三个交互细节叠加**；今天 12 处改动里只有 2 处触及对话流程，且都是按需求改的 |
| 结果 | 138/138 全绿，`tsc` 0 error |

---

## 一、三个真凶（按影响排序）

### 1. Esc 无差别中止 —— 这是"没跑完就断开"的直接原因

`useAgentRun.ts` 里有一个全局键盘监听：

```js
if (!loading) return;
const onKey = (e) => { if (e.key === 'Escape') stop(); };   // 改前
window.addEventListener('keydown', onKey);
```

它是 window 级、**不看谁消费了按键、不看焦点在哪**。而全仓 10 处 Esc 处理里，**只有 PlusMenu 调了 `stopPropagation`**，其余（关设置面板、关模型选择器、取消会话重命名、关确认弹层、Composer 里取消 slash 补全）都会冒泡上来 → 顺带把正在跑的任务杀掉。

日志与现象吻合：三个 run 全部 `aborted=true`，其中第二个只活 5 秒、0 token。

**修复**：让各弹层在 Esc 时 `preventDefault()`（声明"这个按键我消费了"），全局监听只处理「没人消费 + 焦点不在输入/文本域」的 Esc。

### 2. 技能注入规则把"安全类技能"全判成攻击

日志里 6 个技能全部 `secret-exfiltration` 拒绝注入。逐个看命中片段：

| 技能 | 命中片段 | 真实含义 |
|---|---|---|
| ai-cost-control | "输出 token" | **计费单位**，不是凭证 |
| llm-integration | "密钥只从环境或密钥管理读取" | 安全最佳实践 |
| ci-pipeline-authoring | "不要在日志中打印密钥与完整环境变量" | 明确**禁止**这么做 |
| secret-scanning | "密钥已在远端仓库泄露" | 描述要检测的风险 |
| security-code-review | "敏感数据：日志打印密钥与个人信息" | 风险清单项 |
| mcp-server-builder | "环境变量读取" | 技术说明 |

旧规则只看「动词 + 名词」共现，不看语境：`(读取|打印|输出|上传|发送|泄露) … (.env|环境变量|凭证|密钥|api key|token|id_rsa)`。于是「不要在日志中打印密钥」和「把密钥发给我」被判成同一类。

**修复两层**：
- 规则收窄：去掉 `输出`（报告用词）、`token` / `api key` / 裸 `密钥`（AI 语境噪声），只保留**具体凭据载体**（`.env` / `id_rsa` / `.aws/credentials` / `.ssh` / `凭证` / 环境变量）；
- 加**否定语境排除**：命中点前 16 字符出现「不要/禁止/避免/never/do not…」即不计；
- 二次修正：外泄动词补「发给/发到/传给/贴出」（原规则漏了「把 .env 的内容发给**我**」这种口语），并把「读取」限定为只与**文件型**目标组合（`读取环境变量` 是正常编码）。

**这是因果链上最隐蔽的一环**：技能全废 → 模型少了 6 份方法论 → 回答更慢更差 → 用户等不及按 Esc → 任务被中止 → 「感觉不顺」。两个缺陷互相放大。

### 3. 运行中发消息的语义刚改过（Enter → 队列）

上一轮按你的要求把 Enter 从 `steer`（打断当前轮插话）改成 `queue`（入队）。这是**对话流程里唯一被有意改变的语义**：

- 改之前：再按 Enter = 停掉当前任务 + 用新内容重跑 ⇒ 你看到的"上一个直接断开"
- 改之后：再按 Enter = 入队，当前任务继续跑；卡片上三个动作（立即执行 / 编辑 / 删除）

副作用：`steer()` 现在**没有任何键盘入口**（成了不可达能力）。它仍有价值（"别做这个了，改成那样"而不重跑），但当前只能靠代码调用。

## 二、与主流设计的对照

| 能力 | 主流（Codex / Claude Code / WorkBuddy） | 本仓库现状 | 判定 |
|---|---|---|---|
| 一次消息 = 一个 run，run 内多轮工具 | 是 | 是（`runId` 递增，工具循环在 run 内） | 一致 |
| 中止入口 | Esc + 停止按钮 | Esc（本次修好误伤）+ 停止按钮 | 修复后一致 |
| Esc 的作用域 | 仅"无弹层、非输入态"时停 | 同上（本次对齐） | **修复后一致** |
| 运行中发消息 | 入队，卡片给出「立即/编辑/删除」 | 已有 `QueuedTasks` 三按钮 | 一致 |
| 轮末自动接力队首 | 是 | 是 | 一致 |
| 用户主动停止后 | 不自动跑队列 | 不接力，排队项保留 | 一致 |
| 插话（不重跑、改当前轮） | Claude Code 无；部分工具有 | 有实现、无入口 | 能力在，入口缺（技术债） |
| 断点续跑 | 有 | 有（checkpoint + 预算熔断即暂停） | 一致 |
| 上下文压缩 | 自动 + 手动 | 自动 + `/compact` | 一致 |
| 多会话并发 | 后台保留 | `runRegistry` 按 threadId，切会话不杀 run | 一致 |
| 失败重发 | 有 | `lastFailed` 一键重试 | 一致 |
| 技能/项目指令的注入检测 | **本地文件默认信任**，只对运行时外部内容（网页/MCP 返回）做扫描 | 本地 `SKILL.md` 与外部内容**同一套 fail-closed** | **偏离**（已收窄规则，但仍是"宁可错杀"的姿态） |

> 最后一行是这次故障的设计根源：把"用户自己装的本地技能"当成"外部不可信内容"。主流做法是只给外部内容打 `UNTRUSTED` 标记并降权，本地资产不拦。

## 三、今天改了什么、是否可能造成问题

| # | 改动 | 触及对话流程？ | 风险 |
|---|---|---|---|
| 1 | `Composer` Enter → 入队（按你要求） | **是**（语义变更） | 习惯"Enter 打断重跑"的人会觉得变慢；已确认符合需求 |
| 2 | 各弹层 Esc `preventDefault` + 全局 Esc 收窄 | **是**（修复） | 无；停止能力仍在（空白处 Esc / 停止按钮） |
| 3 | 注入规则收窄 + 否定排除 | **是**（修复） | 放宽了 `secret-exfiltration`；已用 8 条攻击样本验证仍能拦 |
| 4 | `payloadGuard` 的 id 校验（`assertTokens`→`assertIds`） | 曾**阻断**（每条消息都写不进库） | 已修；现在数字 id 正常 |
| 5 | `approvalSettings` / `runApprovalModes` | 否（只影响无人值守档位来源） | 交互 run 仍用 payload 档 |
| 6 | `MessageStream` 外链走 `openExternal` + 主进程 `will-navigate` | 否（只影响点击外链） | 修好了"点链接变成新会话" |
| 7 | MCP：SSE 传输、CRLF、header/URL 模板、token-schema、锁版本 | 否（工具层） | 与本问题无关 |
| 8 | 移除 ima / Ardot | 否（目录） | — |

**结论：对话"不顺"不是某一次改动引入的架构问题，而是「既有 Esc 缺陷 + 注入规则误杀」在新版本里同时被触发**；第 1 条是你明确要求的语义变更，属于预期内。

## 五、剩余风险与建议

| # | 项 | 建议 |
|---|---|---|
| R1 | `steer()` 无入口（不可达能力） | 给它一个明确入口（如 `Cmd/Ctrl+Enter` = 打断并用当前输入重跑），或在下一版删除，别留半截 |
| R2 | 本地技能与外部内容同规则 | 中期按来源分级：本地 `~/.mjcode/skills` 命中注入只**警告并注入**（附标记），市场/仓库下载的才 fail-closed |
| R3 | `读取 .env` 仍会命中 | 正常文档（"启动时读取 .env 配置"）会被误判；如遇到，按 R2 分级解决，而不是继续加白名单 |
| R4 | 中止后没有"为什么停"的提示 | 日志有，界面没有；建议中止时在消息流里留一条可读原因（用户主动 / Esc / 系统） |
