# MJCode 0.5.5-beta

在 `0.5.0-beta` 之上的一版修复。核心是**让「定时任务能真正跑出产物」**，以及两个长期被误判成「模型不行」的问题。

> 完整改动：`v0.5.0-beta..v0.5.5-beta`（41 个提交）。

---

## 定时任务：从「显示成功但找不到文件」到「产物必须落盘」

这一版之前，一条「抓 100 篇新闻，输出 md」的定时任务会显示成功，但磁盘上什么都没有。查下来不是模型、也不是权限，而是三层问题：

- **提示词从没要求写文件**：定时通道用的是 `customSystemPrompt || BASE_PROMPT`——**整体替换**而不是追加，把 BASE_PROMPT 里「你会用 write_file，默认在当前目录读写」整段能力说明丢了，只剩一句「产出精炼可读的结果摘要」。模型在回答里贴一张 markdown 表格，完全符合它收到的指令。
- **没有任何交付校验**：判定只看「有没有自述未完成 / 有没有工具调用」，从不看文件到底写没写。
- **越界写是慢死**：一次白名单外写入要等审批超时 120 秒才被拒；重试 5 次就撞 10 分钟墙钟，死因被写成「执行超时」，把真正的原因盖掉。

现在：

- **产物有固定落点**：`~/Documents/.MJCoder/output/<任务名>/`，目录名复用归档目录的同一套消毒规则（Windows 保留名、`..`、超长名都处理）。
- **系统提示改为追加**：`appendSystemPrompt` 在 BASE_PROMPT 之后拼接，能力说明不再被顶掉；并写死三条约束——必须写入指定目录、回答只给「一句汇总 + 绝对路径」、读从项目目录、写只写产出目录。
- **新增交付判定**（`scheduledVerdict`）：未完成 → 引擎闸门 → **零文件产出** → 交付降级。`writes` 与 `shellWrites` 任一大于 0 即算有产出（用 `cat > news.md` 写文件也算）；任一计数未知时**不判**——宁可漏判，也不把「文件写了」误判成「没写」。
- **不需要文件的任务可以关掉校验**：任务上的「要求产出文件」开关（默认开），提醒/汇报类任务关掉后不会因为零产出被判失败。
- **越界写立即失败**：白名单内直接执行、白名单外立刻返回结构化错误（实测 7ms），不再干等 2 分钟。
- **中断不再留僵尸**：应用在任务执行期间退出时，那条 run 会被收敛成失败，并写明「工具调用与输出未收尾，本次数据不可信」——不再永远显示「运行中」。
- **可追溯**：定时任务的 trace 现在按 runId 落盘（此前只有一条 `verify_result`，出事时无法还原它到底调了什么）。

### 定时任务现在能并行

同一句话在对话里能跑出 4 个 Agent 并行抓取，在定时任务里却只能串行——差别是**工具表少一个工具**：定时通道只有 23 个工具，没有 `orchestrate_task`。

现已补齐，并要求子 Agent 只回要点、不写文件（并发写同一个 md 会互相覆盖），由父任务汇总后落盘。单任务墙钟相应从 10 分钟放宽到 20 分钟，轮次 40、token 预算 400k（100 篇 ≈ 10 批 × 2 轮，原来的 20 轮零余量）。

## 模型按会话绑定

此前只有一个全局的「最后一次用过的模型」，切会话模型根本不变。现在：

- 每个会话记住自己的模型，切回去就是它上次用的那个；
- 在一个会话里换模型，只影响这个会话；
- 新会话沿用「最后一次用过的」；
- 定时任务保持每个任务自己的模型快照。

实现上刻意**不做**「监听模型变化就自动保存」：切会话时 React 会先用「新会话 id + 旧模型」渲染一次，自动保存会把旧模型写进新会话、冲掉它原本的记录——表面看最终值对了，实际已经丢数据。

## 停止按钮不再「点了没反应」

两个独立原因：

- **空分支早退**：父任务已收尾时 `inFlight=false`（早退），而 abort 引用又已被清空，三个分支全不成立，函数静默返回——编排组还在后台跑，点击等于空操作。
- **界面复位被落库挡住**：`setLoading(false)` 排在持久化之后，落库慢一拍，用户就一直看着「运行中」。

现在停止会按 run 直接中止，并**取消该会话下所有未结束的编排组**（不误伤其他会话的后台任务）；界面复位提前到同步段，先让界面收敛再落库。

## 升级须知

- dmg 使用本机 Apple Development 证书签名，**未做 Apple 公证**。首次打开如提示「无法验证开发者」，右键 →「打开」即可。
- 定时任务的产物目录变了（新增 `output/` 子目录），旧的归档仍在 `~/Documents/.MJCoder/tasks/` 下，两者并存。
- 已在运行的定时任务不受影响；但如果某个任务本来就不产生文件（只做 git 提交 / 只做汇报），请在任务卡片上关掉「要求产出文件」，否则会被判「未产出文件」。
