## 七、执行时最容易踩的四个坑（本轮实证）

1. **不要用 md 行号当锚点**。技本文档在本轮 7 分钟内出现 3 个版本（662→714 行）；用「章节标题 + sha256」定位。
2. **不要在并发写入期跑全量 `npm test`**。会得到「每次失败集不同、单跑又全绿」的假回归，去修不存在的 bug。
3. **新增测试文件必须 `.ts/.tsx` 或放对位置**。`docs/harness-r7/04-test/check.mjs` 刻意避开 `desktop/test/`，否则会被 `run-all.mjs` 发现式扫描计入基线（C-01/C-03/C-05 全变）。
4. **验收「期望为红」的用例必须先证明基线绿**。基线红 + 变异未生效也返回非零退出，与「变异成功」不可区分——这是最反直觉的假成功。
