# 存量收敛台账（F-017 / B2-B-13）

> 机器可读台账：`docs/harness-r7/legacy-ledger.json`
> 生成器：`desktop/scripts/gen-legacy-ledger.mjs`
> 强制性门禁：`desktop/test/legacy-ledger.test.mjs`

## 1. 这份台账要解决什么

两个存量指标此前都只是**上限**（ratchet），只防恶化、不防挂账：

| 指标 | 原门禁口径 | 当前实测 | 失效表现 |
|---|---|---|---|
| 死 bridge 方法 | `test/bridge-parity.test.mjs:107` 断言**占比 ≤ 40%** | **50 / 224 = 22.3%** | 上限 40% 对 22.3% 毫无压力，50 个可以永远躺着 |
| 裸 `<button>` | `test/ui-conventions.test.js:26` 用 `counts.rawButton <= 258` | **258** | 刚好等于基线，一个都不清也「通过」 |

两者共同的病：**数字只被当成天花板，没被当成待办清单**。没人知道 50 条是哪几类、258 个散在哪些文件、下一轮该先动哪一块 —— 于是永远不动。

本台账把「一个数字」拆成「分组 + 计数 + 处置状态」，让欠账变成可排期的对象。

## 3. 三类处置的含义

每个分组带一个 `disposition` 字段，取值：

| disposition | 含义 | 对下一轮的要求 |
|---|---|---|
| `pending` | **还没动**，欠账仍在（初始值） | 未排期；每轮盘点时优先看大组 |
| `consume` | **已排期消费**：本轮/下轮有 owner、有动作 | 排期内必须让该组计数下降，否则说明排期是假的 |
| `retire` | **已彻底消灭**：该组计数应归零 | 组本身随后从台账消失（计数归零的组不再出现） |
| `exempt` | **经评估接受**这批存量 | 必须在此文档写明理由；之后不再作为欠账追踪，但计数不允许**增长** |

`pending` 之外的三类都必须在本文件对应小节写下理由，否则下一轮无法判断「为什么这组不清」。

> `disposition` 是**人工判断**，生成器算不出来。因此 `--write` 会**保留**已有分组的处置状态（只对新增组填 `pending`），不会把人工判断重置掉。

## 4. 下一轮目标

1. **先清 `market` 组（9 条，最大组）**。它是整条市场链路（search/searchNetwork/listInstalled/inspect/checkPermission/installGit/setEnabled/uninstall/refresh）——要么把渲染层入口接上，要么整组从 preload 摘掉。超过一半是「实现完整但无调用方」，沉默成本最高。
2. **其次 `collab` 组（7 条）**。协同编辑整条链路无入口，需先确认该功能是否仍在路线图上：在 → 接入口；不在 → 整组 retire。
3. **`cua` 组（5 条）走豁免评估**。录制回放功能由独立面板驱动，需确认其调用方是否走别的前缀；确认后标 `exempt` 或接入口。
4. **裸 button 不设清零目标**。258 里多数是 5 类刻意豁免，硬转会引入可感知 UI 差异。下一轮只要求：**基线不再上浮**，并把 Top 3 文件（`Onboarding.jsx` 31 / `Composer.tsx` 20 / `ModelsTab.tsx` 16）逐文件评估是否可以整批转 `ui/Button`。
5. **本批（T5-10 中断）无新增欠账**：新增的 `teamsInterrupt` 桥在看板里已有调用方，不进入死桥；同时把 `workerText.js` 从 `workerPool.js` 抽出，只为守住 800 行软档，不涉及 bridge 口径。`teams` 组维持 4 条 `pending`。

## 5. 怎么更新台账

```bash
cd desktop

# 只看现算结果（人眼核对，会把每组成员打到 stdout）
node scripts/gen-legacy-ledger.mjs

# 变更后更新台账（保留已有 disposition）
node scripts/gen-legacy-ledger.mjs --write

# 校验台账与现算一致（CI 门禁）
node test/legacy-ledger.test.mjs
```

**任何计数变化（增或减）都会让 `legacy-ledger.test.mjs` 报红**，这是刻意设计：

> 存量变化不是错，但必须同步台账并说明处置。

请按提示重新 `--write`，并回到本文件第 4 节说明这批的处置结论。若是因为**清理**导致数字下降，请在下方「变更记录」追加一行；若是因为**新增**导致数字上升，先确认是否属实，再决定补进哪一类处置。
