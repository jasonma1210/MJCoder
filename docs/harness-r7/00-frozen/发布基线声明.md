**按 HEAD 打包 = 把这 3 项已经做完的修复退回制品之外。** 这是选择「合并当前 diff 后」的唯一决定性理由。

| # | 修复内容 | 落在哪些未提交文件 | 若按 HEAD 打包的后果 |
|---|---|---|---|
| 1 | **MCP 默认注入**（`mcp:listTools` 只回已连接服务） | `desktop/main/ipc/mcp.js` | 第五/六轮承诺的 MCP 行为在制品中**不生效** |
| 2 | **`task_groups.project_path` 迁移（v7）** | `desktop/main/db/index.js`、`desktop/main/main.js`、`desktop/main/taskStore.js` | 编排组与项目路径的绑定在制品中**缺失** |
| 3 | **记忆 `conversationId`**（修 `model_conclusion` 孤儿行 `conversation_id = NULL`） | `desktop/main/ipc/localData.js`（IPC 入参接受并透传 `conversationId`）＋ `desktop/renderer/src/hooks/useAgentRun.ts`（调用方传入 `currentThread?.id`） | `model_conclusion` 记忆落 `conversation_id = NULL`，会话层记忆**无法按会话召回** |

> **对上游两处表述的实测更正（编码阶段）**：第 3 项修复**跨两个文件**，缺任一环都拿不到 `conversationId`。

> - 任务下发只把它归属到 `desktop/main/ipc/localData.js`。
>
> 两处各说了一半，故本表按两文件记录。依据：`git diff -U0 -- desktop/main/ipc/localData.js desktop/renderer/src/hooks/useAgentRun.ts | grep conversationId`
